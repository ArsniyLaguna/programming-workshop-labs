# Подготовка к защите ЛР 2 и ЛР 3

## Общая история проекта

Мы прогнозируем две числовые величины — отопительную и охлаждающую нагрузку — по конфигурации здания. Объект датасета — одна строка с параметрами конфигурации. В ЛР 1 сохранено разделение: 614 строк на обучение и 154 на тест. ЛР 2 и ЛР 3 продолжают работу с теми же строками. `source_row` — исходный индекс строки для сопоставления, не входной признак модели.

## ЛР 2: что рассказать за 2–3 минуты

В четырёх исходных входных столбцах были пропуски: `Relative Compactness`, `Reactor Wall Area`, `Overall Height`, `Orientation`. Цели полные. Сначала сравнили способы заполнения: медиана/мода, KNN и случайный лес. Правильные значения настоящих пропусков неизвестны, поэтому в обучающей части трижды скрывали 20% известных значений и сравнивали восстановление с исходными. Для числовых столбцов использовали MAE (средняя абсолютная ошибка, меньше лучше), для категории `Orientation` — accuracy (доля верных классов, больше лучше). Для трёх числовых столбцов выбрали лес, для ориентации — моду. Затем заполнили train и test, используя только информацию train, и закодировали две номинальные категории one-hot. Итог: 16 числовых входных столбцов, 614/154 строк, пропусков нет. Целевые значения не менялись.

### Возможные вопросы по ЛР 2

| Вопрос | Короткий ответ |
|---|---|
| Зачем делить данные до заполнения? | Статистики и модели заполнения должны обучаться на train. Использование test заранее завысило бы честность последующей оценки. |
| Почему нельзя измерить качество на настоящих пропусках? | Их правильные значения неизвестны. Поэтому проверяем на искусственно скрытых известных значениях. |
| Зачем три повтора маскирования? | Уменьшить зависимость выбора метода от одного случайного набора скрытых строк. Seed делает опыт воспроизводимым. |
| Почему MAE для чисел и accuracy для ориентации? | Числовая ошибка имеет величину; у номинальных кодов важен факт совпадения класса. |
| Что делает KNNImputer? | Ищет похожие строки по доступным признакам и восстанавливает пропуск по их значениям. Перед ним нужен общий масштаб признаков. |
| Почему случайный лес? | Для трёх геометрических столбцов он дал наименьшую MAE в проверке на train. Он использует связи между признаками. |
| Почему мода для Orientation? | Среди проверенных методов она дала лучший accuracy; при этом качество низкое, поэтому восстановленную ориентацию нельзя считать достоверно известной. |
| Зачем one-hot, а не оставить коды 2–5? | Коды категорий не задают расстояние и порядок. One-hot создаёт отдельный бинарный столбец для каждого значения. |
| Что происходит с неизвестной категорией в test? | `handle_unknown="ignore"` оставляет нули для признака этой категории, не меняя набор столбцов. |
| Что не меняли? | Разбиение, индекс исходных строк, наблюдавшиеся значения и обе целевые переменные. |

**Важное ограничение:** эксперимент оценивает заполнение на скрытых известных значениях, но не точность будущего прогноза нагрузок. Разбиение из ЛР 1 случайное; близкие конфигурации могут оказаться и в train, и в test.

## ЛР 3: что рассказать за 2–3 минуты

Выброс — необычное значение **одного столбца**. Аномалия — необычное **сочетание признаков в строке**, даже когда каждый признак по отдельности допустим. Взяли шесть числовых входных параметров после ЛР 2. По train посчитали квартили и границы `Q1 − 1,5·IQR` и `Q3 + 1,5·IQR`, показали их на гистограммах и построили ящики с усами. Теми же границами проверили test. Выбросов не оказалось. Обучающие цели рассмотрели отдельно.

Затем стандартизовали шесть входов по train и применили Isolation Forest и LOF. Первый изолирует редкие точки случайными разбиениями; второй сравнивает локальную плотность с соседями. При выбранном пороге 3% Isolation Forest отметил 19 обучающих строк, LOF — 16, пересечение — 4 строки (`source_row` 44, 45, 46, 47). На двухмерной проекции PCA они отмечены на графике. Все четыре — редкие конфигурации с нулевым остеклением и допустимыми числовыми значениями. Подтверждённой ошибки нет, поэтому не удалили ни одной строки. Таблицы флагов сохранены отдельно, данные train/test не изменены.

### Возможные вопросы по ЛР 3

| Вопрос | Короткий ответ |
|---|---|
| Что такое Q1, Q3 и IQR? | Q1 — 25-й процентиль, Q3 — 75-й; IQR = Q3 − Q1, разброс средней половины значений. |
| Почему коэффициент 1,5? | Стандартное эвристическое правило Тьюки для кандидатов на выброс; оно не доказывает ошибку. |
| Почему границы считаются только по train? | Чтобы test не влиял на решения предобработки. |
| Почему one-hot столбцы не проверяли IQR? | У бинарного признака только 0 и 1; правило для непрерывного распределения здесь малоинформативно. |
| Зачем StandardScaler? | Площади имеют гораздо больший числовой масштаб, чем компактность и остекление; без стандартизации сравнение расстояний было бы перекошено. |
| Что задаёт contamination=0.03? | Чувствительность/порог детектора около 3% подозрительных строк, а не истинную долю ошибок. Из-за совпадающих значений число флагов может отличаться от ровно 3%. |
| Что задаёт n_neighbors=20? | Сколько соседей LOF использует для оценки локальной плотности. |
| Зачем два метода и пересечение? | Они ищут необычность по разным принципам. Совпадение даёт более строгий список для ручной проверки, но не доказывает ошибку. |
| Зачем PCA? | Показать шестимерные данные на двумерном графике. Проекция теряет часть информации; здесь она объясняет около 82,4% дисперсии. |
| Почему не удалили аномалии? | Проверка показала допустимые, хотя редкие, конфигурации без остекления. Удаление сократило бы охват модели. |
| Почему цели не включены в детекторы? | Ищем необычные входные конфигурации и избегаем использования ответов для предобработки будущих входов. Цели смотрели только после получения флагов. |
| Почему LOF для test обучен в режиме novelty? | Обычный `fit_predict` оценивает только обучающую выборку; для новых строк нужен режим `novelty=True`. |

**Ограничение:** у нас нет истинной разметки ошибок, поэтому нельзя вычислить precision/recall аномалий. «Аномальный» означает «требует проверки», а не «надо удалить».
